# ADR 014: Границы каталога подрядчиков, проектного КП и сметы

**Статус:** принято  
**Дата:** 2026-09-08

## Контекст

Команде нужен быстрый конструктор мероприятия внутри проекта: общий каталог подрядчиков с актуальными ценами, несколько клиентских вариантов, перенос выбранного состава в смету и генерация презентации. Если использовать живую карточку подрядчика напрямую во всех проектах, последующее изменение цены или описания перепишет историческое предложение. Если сделать КП вторым редактором сметы с автоматической двусторонней синхронизацией, два финансовых источника истины будут конфликтовать.

## Решение

1. Глобальный каталог подрядчиков и проектное КП являются разными доменными сущностями.
2. Подрядчик содержит контакты и несколько предложений; цена принадлежит конкретному предложению, а не подрядчику целиком.
3. При добавлении предложения в проект создаётся типизированный снимок имени, описания, единицы, клиентской/внутренней цены, даты подтверждения и выбранных изображений. Ссылки на исходный каталог сохраняются только для сравнения и явного обновления.
4. Клиентские альтернативы моделируются вариантами и не подменяют revision документа.
5. Отправка или экспорт фиксирует неизменяемый snapshot КП.
6. Перенос в смету односторонний, предварительно показывает diff, выполняется атомарно и идемпотентно. Последующие изменения сметы не меняют КП, а изменения КП не переписывают смету без подтверждения.
7. Новый `ProjectWidget` типа `EVENT_BUILDER` хранит только layout/config; всё содержимое живёт в нормализованных таблицах.
8. Презентации создаются через версионированный adapter и асинхронный export lifecycle. Конкретная PPTX-библиотека выбирается после spike на реальном корпоративном шаблоне.
9. Использованные каталожные сущности деактивируются, а не hard-delete.

## Последствия

- Старые КП и сметы воспроизводимы даже после изменения каталога.
- Нужны дополнительные таблицы snapshots и связи переноса, но исчезает скрытая двусторонняя синхронизация.
- Менеджер получает явное сообщение об устаревшей цене и сам решает, обновлять ли проектный снимок.
- Генератор презентаций можно заменить без переписывания конструктора.
- Для параллельной работы обязательны revision/CAS, conflict UI и `ProjectMutationReceipt` для критических операций.
- Реализация следует ADR 012 и не хранит доменные данные в JSON config виджета.
