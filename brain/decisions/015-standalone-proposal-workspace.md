# ADR 015: Самостоятельное КП и единое рабочее пространство

Статус: принято владельцем продукта по ТЗ V2 07.10.2026.

## Контекст

Менеджер должен собирать предложение до создания проекта. Вложенная проектная панель смешивала каталог, настройки и финансовые данные и мешала подбору услуг.

## Решение

- `StandaloneProposal` хранит контекст лида, владельца и происхождение конвертации. Дерево не дублируется: существующий `ProjectProposal` принадлежит либо проекту, либо самостоятельному КП. XOR обеспечен CHECK в PostgreSQL.
- `/proposals/[id]` — единый редактор для обеих форм владения. Виджет проекта содержит сводку и вход в тот же редактор на весь экран, без вложенного AppShell и дублирования логики; каталог — переход к списку КП.
- Создание проекта или привязка переносит дерево без копирования в `Serializable`-транзакции с revision/CAS. Источник остаётся для истории; после конвертации отдельное редактирование источника не допускается.
- Общие структурные мутации живут в серверном сервисе. Старый проектный маршрут остаётся совместимым адаптером с дополнительной проверкой projectId.
- Итог рассчитывается отдельно для каждого варианта. В базовый бюджет входят только PRIMARY; OPTIONAL и ALTERNATIVE показаны отдельно. Неизвестная цена не превращается в достоверный ноль. FROM/RANGE обозначают предварительный нижний итог.
- Временное КП не является фактом выручки/LTV. При объединении заказчиков его FK переносится, как у самостоятельных смет.
- Новый экран сохраняет только явно подтверждённые изменения на сервере; не восстанавливает локальную копию поверх серверной. При 409 требует загрузки текущей версии.

## Последствия и границы этапа

Нужна отдельная additive-миграция до выкладки приложения. Общий migrate deploy нельзя использовать для базы, где старые SQL применены вручную без Prisma history.

Печать клиентского представления — временный способ сохранить PDF через браузер, не официальный версионированный экспорт. Неизменяемые client-safe snapshots, PDF/export history, batch undo/redo, структурные шаблоны, полный диапазон цен и PPTX остаются следующими этапами по ADR 014 и ТЗ V2.

## Уточнение надёжности — 08.10.2026

- Для обычных явных правок студия отправляет UUID `mutationId`. `ProposalMutationReceipt` принадлежит КП и автору, содержит hash запроса, итоговую revision и серверную обратимую delta. Повтор подтверждённого UUID возвращает актуальную модель без второй записи; повтор UUID с другим payload запрещён. Legacy adapter без UUID остаётся совместимым, но не получает undo.
- Delta хранит только изменившиеся записи, включая исходные ID, приватные поля, каталожные снимки и ссылки переноса. Она вычисляется из серверного состояния, не принимается из браузера. На этом этапе для вычисления delta читается дерево до/после операции; scoped capture и серверные batch mutations остаются оптимизацией следующего этапа.
- Undo — `RESTORE_CHANGE` с UUID исходной команды. CAS и Serializable обязательны. Проверяется автор, неизменность затронутых записей и отсутствие новых чужих потомков у удаляемого родителя. Компенсация сама получает receipt; redo отменяет её. Один receipt нельзя компенсировать дважды разными командами.
- Ранее перенесённая строка сметы не откатывается. Удаление КП-позиции обнуляет FK receipt переноса; восстановление возвращает исходный ID и перепривязывает только сохранившиеся ссылки с пустым FK. Данные сметы не меняются.
- История браузера ограничена 50 командами; сохраняется в локальном журнале по пользователю/КП и восстанавливается лишь при совпадении revision. Загрузка новой серверной версии обнуляет текущий undo/redo, чтобы не отменять работу коллег.
- Локальный журнал форм версии 1 хранит поля текущих несохранённых форм, один отправленный запрос и ограниченную очередь `queued` (до 50). Старые журналы читаются с пустой очередью. Записывается на изменение поля, до принятия команды в очередь и перед запросом; недоступность localStorage не позволяет потерять отправляемую форму. После перезагрузки восстановление явно возвращает поля **в форму**, а возобновление очереди требует отдельного согласия и совпадающей revision. При другой revision доступны скачивание копии и сохранение серверного состояния; автоматического merge/overwrite нет.
- Неопределённый сетевой результат блокирует новые записи до проверки того же UUID. Native undo текста в input/textarea не перехватывается. Конвертация, перенос в смету и экспорт не входят в историю undo; это отдельные действия.
- Новая таблица закрыта RLS/revoke для прямых anon/authenticated клиентов; приложение работает через существующие DB-backed sessions и серверный Prisma. Миграция `20261008120000_proposal_command_receipts` обязательна до выкладки.
- `MOVE_SECTION` меняет только порядок своего варианта; `MOVE_ITEM` допускает перестановку и перенос между его разделами, но не между вариантами. Сервер принимает anchor `beforeId` (null — конец), проверяет его владение, уплотняет sortOrder и сохраняет ID/снимки/transfer links. Команды входят в тот же журнал/undo; hover и отменённый pointer gesture не отправляют запрос.

## Фоновая очередь и проектный полноэкранный редактор — 08.10.2026

- Обычное сохранение не блокирует подбор, навигацию и новые правки существующих услуг. Команды отправляются строго по одной; `expectedRevision` фиксируется при первом dispatch. Повтор сети/5xx до двух раз использует неизменные UUID и payload (таймаут попытки 20 с). CAS и Serializable не меняются.
- Локальная проекция даёт мгновенную обратную связь, но не создаёт каталожных снимков на сервере. Временные ID новых услуг не допускаются в редактирование/перенос до подтверждения. Для разделов/вариантов ждём настоящие server IDs, сохраняя доступ к остальному редактору.
- 409 останавливает очередь и сохраняет отклонённую команду, включая поля закрытой формы. Неопределённый результат сохраняет pending UUID. Более новая серверная revision из ответа receipt не становится основанием для автоматического replay локальной очереди после reload.
- Undo/redo, конвертация, перенос и печать доступны после подтверждения всей очереди. Ответ старой команды не закрывает и не очищает новую форму. Fullscreen закрывает сначала инспектор; редактор с незавершённой очередью защищён от размонтирования, а перезагрузка/уход предупреждают об изменениях.
- Новых таблиц/миграций для этой итерации нет. Полноэкранная печать скрывает фон проекта и внутренние суммы.
