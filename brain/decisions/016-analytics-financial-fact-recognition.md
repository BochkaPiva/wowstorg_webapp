# ADR 016 — Единый финансовый факт аналитики

Дата: 08.10.2026. Статус: принято после согласия владельца продолжить исправления по аудиту.

## Контекст

Независимые периоды обзора и клиентов давали разные рейтинги. Пересечение дат завершённого мероприятия повторяло бюджет в соседних месяцах; Excel использовал другую дату. Округление каждого агрегата до рублей мешало сверке.

## Решение

- Обзор, проекты, клиенты и реквизит используют общий период. Бонусы и сверка сохраняют независимые периоды. Настройки v2 мигрируют в v3, базовый период берётся из сохранённого обзора.
- Финансовый факт — самостоятельная закрытая заявка по endDate или завершённый FULL-проект по eventEndDate, при отсутствии окончания по eventStartDate. Каждая работа учитывается один раз, целиком, без распределения бюджета по дням.
- Прогноз остаётся отдельным: активные самостоятельные заявки и активные неархивные проекты, интервал которых пересекает период. Суммы прогнозов соседних периодов не аддитивны.
- Уточнение 09.10.2026 по прямому запросу владельца: завершённый проект без обеих дат мероприятия входит в факт по календарному дню закрытия в `Asia/Omsk`. Источник — `archivedAt`; при его отсутствии — последний записанный переход `PROJECT_UPDATED.changes.status` в `COMPLETED`. Даты мероприятия имеют приоритет. `createdAt`/`updatedAt` и название не используются. Активные проекты без дат и завершённые без подтверждённой даты закрытия остаются вне итогов, в отдельном раскрытии и листе Excel.
- Источник цены и прибыли не меняется: existing pricing helpers, все версии includeInProjectTotals, fallback чернового реквизита. Заявки с projectId исключены из самостоятельного финансового результата; это не подтверждает, что каждая из них включена в учитываемую смету.
- Общий in-memory ledger фактов питает динамику и Excel. Деньги агрегируются в копейках; подписи UI сохраняют до двух знаков. Деление бонусного пула распределяет остаточную копейку так, чтобы сумма долей совпадала с пулом.
- Полный каталог реквизита и полный набор проектных рисков используются в таблицах. Top-N — только для лидерских списков. Спрос в проектах отделён от самостоятельной выручки.
- Сверка сравнивает весь файл с всем фактом сайта за период снимка, а не только matched-строки. Внешние снимки и бизнес-записи не изменяются.

## Последствия

09.10.2026 владелец уточнил: закрытие не всегда совпадает с месяцем мероприятия. В аналитике явно показывается запасной учёт по закрытию и общий список проектов, требующих уточнения дат (независимо от периода). WOWSTORG может скорректировать **только даты мероприятия** завершённого проекта через отдельный `PATCH /api/projects/[id]/event-dates`, в том числе в архиве. Это узкое исключение из read-only: не меняет статус, архив, сметы, заявки или резерв. Запись атомарна с журналом, вход строгий, ожидаемые прежние даты защищают от перезаписи коллеги. После сохранения даты мероприятия имеют приоритет над закрытием, все периоды клиентского кэша сбрасываются. Общий `PATCH /projects/[id]` по-прежнему запрещает любые архивные правки; схему БД не меняем.

Итоги завершённых работ аддитивны по непересекающимся периодам, рейтинги сопоставимы при одинаковых датах. Старые суммы отдельных месяцев могут измениться из-за устранения двойного счёта; копейки становятся видимыми. Факт по-прежнему управленческий, не банковские поступления и не бухгалтерский отчёт. Без дат и корректной включённости смет система не может гарантировать полноту первичных данных. Миграция БД не требуется; авторизация WOWSTORG и ADR 008 сохраняются.
