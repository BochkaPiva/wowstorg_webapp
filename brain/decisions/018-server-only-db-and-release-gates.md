# ADR 018 — Серверный доступ к БД и обязательные проверки выпуска

Дата: 10.10.2026. Статус: принято.

## Контекст

Сессии проекта — cookie + таблица Session (ADR 003), все бизнес-запросы идут через серверный Prisma. Supabase Auth/Data API не используются клиентом. При этом public-таблицы имели grants для API-ролей, часть без RLS: доступ обходил проверки приложения.

## Решение

- Включить RLS без FORCE на всех public-таблицах; отозвать права PUBLIC/anon/authenticated на таблицы, последовательности и public-функции. Отозвать default privileges текущего создателя миграций (postgres). Не добавлять политики auth.uid(): это другая система авторизации.
- Серверный владелец таблиц / BYPASSRLS и service_role сохраняют необходимые права. Auth/storage схемы и buckets не меняются. Ключ service_role остаётся серверным.
- Новые business-таблицы явно закрывать RLS/revoke. Read-only `scripts/security/check-db-access.mjs` проверяет эффективные права, включая наследование PUBLIC, а не только наличие policies.
- `npm run build:verified`: lint-ratchet → unit tests → production audit → Next build. GitHub CI отдельно проверяет чистый PostgreSQL и настоящий HTTP-путь входа/КП/экспорта.
- Включить тот же build command на Vercel. Он блокирует неуспешную проверку качества, но не заменяет GitHub job миграций и защищённую ветку. Production migrations не запускаются при сборке.
- 164 существующие ESLint-ошибки сохраняются как измеряемый долг, а не отключённые правила. Новая ошибка по файлу/правилу ломает gate. Baseline нельзя расширять без ревью.

## Последствия

Браузерный Supabase Data API больше не является путём к бизнес-данным. До возможного включения такого доступа потребуется отдельный ADR и модель прав. PUBLIC EXECUTE для новых PostgreSQL-функций отзывается глобальным default privilege: schema-local revoke не переопределяет глобальный default grant.

Откат старых grants означает возврат уязвимого состояния и допустим только при подтверждённой необходимости. Снимок ACL/RLS хранится локально вне Git. Репозиторий остаётся публичным до отдельного решения владельца.
