# ADR 021 — Общий серверный лимит попыток входа

Дата: 10.10.2026. Статус: принято.

## Решение

Сохранить cookie/Session авторизацию (ADR 003) и существующие пароли. Перед входом и первой активацией использовать общие атомарные счётчики PostgreSQL, а не память Vercel Functions:

- 8 попыток для пары сеть + точный логин за 10 минут;
- 40 попыток для логина из всех сетей за 10 минут;
- 60 запросов входа/активации с одной сети за 10 минут, до разбора JSON.

Считаются все попытки, включая успешные. Окно начинается первым запросом; отказ не продлевает его. После истечения следующий запрос начинает новое окно. Превышение возвращает 429 с `Retry-After` и понятным сообщением. Существующие сессии и флаги пользователей не меняются. При недоступности счётчиков вход закрывается с 503, но не обходится без лимита.

`INSERT ON CONFLICT` атомарно увеличивает счётчик с ограничением максимумом limit + 1. Account/pair фиксируются короткой транзакцией в одном порядке блокировок; bcrypt вне транзакции. Просроченные более суток счётчики удаляются порциями до 100 с `SKIP LOCKED` и индексом expiresAt.

В Vercel доверять только перезаписываемому платформой `x-vercel-forwarded-for`, при автоматически установленном `VERCEL=1`. IPv4-mapped IPv6 приводится к IPv4; IPv6 группируется по /64. Отсутствующий/некорректный доверенный адрес — 503. Вне Vercel не доверять произвольным forwarded headers: консервативный общий бюджет `non-vercel`. Для другого хостинга потребуется явный проверенный proxy adapter; нельзя просто выставить `VERCEL=1` на сервере, доступном напрямую.

Ключи — SHA-256 с namespace и сериализованными частями, без открытых логинов/IP/паролей. Это псевдонимизация, не шифрование. Таблица закрыта RLS/revoke по ADR 018; данные счётчиков не выдаются клиенту. Новую миграцию применять до выпуска кода; сборка Vercel не применяет её.

## Ограничения

Распределённая атака может временно исчерпать общий account-бюджет: это сознательный компромисс защиты от перебора, не постоянная блокировка аккаунта. Это не защита от всего DDoS и не замена MFA. Общий офисный IP делит IP-бюджет. При расследовании допускается сброс только точно определённых счётчиков, не изменение паролей/прав.

По решению владельца первая активация по логину, отсутствие MFA и текущий состав администраторов не меняются. Если появится новый pending аккаунт, риск активации остаётся: лимитер его не устраняет.

## Проверки

Unit tests проверяют доверие к proxy, нормализацию IPv6, границы лимитов, fail-closed и порядок route guards. HTTP smoke на изолированной БД проверяет параллельные запросы, общий login/first-login бюджет, автоматическое истечение, очистку, сохранение действующих сессий и существующих паролей.
