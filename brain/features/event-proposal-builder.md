# Конструктор мероприятий и КП

## Цель

Дать команде WOWSTORG быстрый сценарий сборки нескольких вариантов мероприятия из актуального каталога подрядчиков, переноса выбранной комплектации в смету и генерации клиентской презентации.

## Текущее состояние

Первая рабочая вертикаль реализована 08.09.2026: каталог, фотографии, предложения и история цены; проектные варианты и разделы; снимки каталожных данных; ручные позиции; CAS-защита от перезаписи; идемпотентный перенос в основную смету. Глобальный каталог показывает подрядчиков карточками со всеми услугами и ценами без отдельного экрана просмотра. В проекте подбор раскрывается полноширинной галереей, явно показывает целевой раздел и уже добавленные позиции; фотографию подрядчика можно загрузить сразу при создании карточки. Генератор PPTX/PDF остаётся следующим отдельным этапом и начнётся после получения реального корпоративного шаблона.

07.10.2026 подготовлено ТЗ V2 после продуктового аудита первой вертикали. Текущая проектная панель признана переходной: она смешивает каталог, структуру, финансы и настройки на одном полотне. Целевая модель — самостоятельная полноэкранная «Студия КП», единая для временных и проектных предложений; в карточке проекта остаётся компактная сводка. Подробная спецификация: [`docs/EVENT_PROPOSAL_WORKSPACE_V2_SPEC.md`](../../docs/EVENT_PROPOSAL_WORKSPACE_V2_SPEC.md).

## Границы первой поставки

07.10.2026 реализован первый срез V2: `/proposals` — общий список и временные КП; `/proposals/[id]` — единая студия с outline, составом и контекстным инспектором. В проекте тяжёлая панель заменена компактным launcher. Из каталога «Составить КП» открывает форму без обязательного проекта. Поддержаны основные/альтернативные/опциональные услуги, собственные позиции, текст для клиента, подтверждаемый перенос в смету и конвертация дерева КП в проект без копирования. Сохранение форм явное; stale revision возвращает 409, не переписывает сервер и сохраняет введённые поля. Browser Print/PDF — промежуточный вывод клиентского вида, **не** генератор PPTX, не immutable export и не отдельный обезличенный client API.

08.10.2026 обе additive-миграции студии применены пользователем через SQL Editor; read-only preflight подтвердил схему. Первый релиз V2 (`4faf71f`) выложен из `master`, production READY. Журнал старых миграций расходится с фактической схемой: нельзя автоматически запускать все pending migrations. Подробности проверки и следующие этапы: [`docs/EVENT_PROPOSAL_V2_IMPLEMENTATION_STATUS.md`](../../docs/EVENT_PROPOSAL_V2_IMPLEMENTATION_STATUS.md).

- Только внутренние пользователи WOWSTORG.
- Без кабинета подрядчика, автоматической доступности по датам, CRM-переписки и публичного клиентского выбора.
- Без произвольного редактора слайдов и без AI-генерации текста.
- Генерация презентации идёт отдельным этапом после проверки реального корпоративного PPTX.

## Затронуто

- Prisma: категории, подрядчики, предложения, контакты, assets, история цен, проектные КП/варианты/разделы/элементы, snapshots и связи со сметой. Модели export lifecycle добавляются вместе с генератором презентаций.
- API: `/api/contractors/*`, `/api/contractor-categories/*`, `/api/projects/[id]/proposals/*`.
- UI: рабочий каталог `/contractors`, новый project widget `EVENT_BUILDER`, полноэкранный конструктор desktop/mobile.
- Storage: фотографии подрядчиков, PPTX/PDF exports и системная папка проекта `Коммерческие предложения`.
- Смета: только явный односторонний перенос в существующие `CONTRACTOR` sections.

## Инварианты

- `ProjectWidget` хранит layout/config, но не содержимое КП.
- Каталог хранит актуальные данные; КП, экспорт и смета хранят снимки.
- Обновление каталога не переписывает прошлое КП автоматически.
- Несколько клиентских вариантов не являются версиями документа.
- Внутренние расходы, контакты и заметки не попадают в клиентский export.
- Перенос в смету идемпотентен, выполняется в `Serializable` транзакции, проверяет revision КП и атомарно увеличивает revision сметы.
- Архивный проект read-only.
- Использованные подрядчики и предложения деактивируются, а не удаляются.
- Цена поддерживает `фиксированная`, `от`, `диапазон`, `за человека/час/день/единицу`, `по запросу`.

## Этапы

1. Spike корпоративного PPTX и фиксация adapter decision.
2. Каталог подрядчиков, категории, предложения, фото и история цены.
3. Проектные КП, варианты, разделы, каталог-панель, autosave/CAS и mobile UX.
4. Diff и безопасный перенос в смету.
5. Асинхронная генерация PPTX, ProjectFile и export history.
6. Пилот, метрики, пакетный импорт и напоминания об устаревших ценах.

Базовая подсказка следующего шага работает без автоматических правок. Следующая UI-итерация добавляет последовательную фоновую очередь без глобальной блокировки при обычном сохранении, компактный статус и тот же редактор в полноэкранном блоке проекта. Новых миграций эта итерация не требует. Статус, проверки и оставшиеся границы — в [`docs/EVENT_PROPOSAL_V2_IMPLEMENTATION_STATUS.md`](../../docs/EVENT_PROPOSAL_V2_IMPLEMENTATION_STATUS.md).

6. Client preview и PDF на существующем `pdf-lib`.

## Приёмка

- [ ] Типовое КП из 5–8 разделов собирается за 5–10 минут.
- [x] Один подрядчик имеет несколько предложений и категории определяются предложениями.
- [x] Дата подтверждения цены выставляется автоматически при её изменении и имеет историю.
- [x] Каталожное обновление не меняет уже собранное КП.
- [x] Два пользователя не могут тихо перезаписать работу друг друга.
- [x] Повторный перенос в ту же смету не создаёт дубли.
- [x] Студия поддерживает Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z и Ctrl+Y для подтверждённых правок, включая удаление разделов/услуг.
- [x] Неподтверждённый запрос повторяется с тем же UUID; локальные поля восстанавливаются явно и не перезаписывают новую revision.
- [x] Разделы и услуги переставляются drag-and-drop, кнопками и клавиатурой; перенос услуги между разделами сохраняет снимок и поддерживает undo/redo.
- [x] До трёх вариантов сравниваются по разделам/услугам, клиентским ценам и количествам; различия фильтруются, неизвестные бюджеты не обещают экономию. Режим работает без записи и имеет последовательный мобильный вид.
- [x] Итоги конструктора и созданных строк сметы совпадают.
- [x] Client payload/PPTX не содержит внутренних цен и заметок (allowlist, unit tests; проверка живого production экспорта отдельно).
- [ ] PPTX проходит smoke test в PowerPoint, Google Slides и LibreOffice без repair warning.
- [ ] Конструктор полноценно работает на телефоне без сжатия desktop layout.
