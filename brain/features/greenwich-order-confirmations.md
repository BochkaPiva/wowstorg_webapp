# Подтверждение актуальности заявок Greenwich

## Цель

Не оставлять ранние заявки Greenwich без проверки до дня выдачи: бот заранее просит сотрудника подтвердить актуальность, предупредить о будущих правках или отменить заявку.

## Затронуто

- Prisma: `GreenwichOrderReminder`, `GreenwichReminderCheckpoint`, `GreenwichReminderResponse`.
- Фоновая задача: `src/server/reminders/reminder-runner.ts`.
- Telegram webhook: `src/app/api/telegram/webhook/route.ts`.
- Тексты и callback-контракт: `src/server/reminders/greenwich-confirmation.ts`.

## Расписание и получатели

- Контрольные точки: за **30**, **14**, **7** и **3** календарных дня до `Order.startDate` по часовому поясу Омска.
- Для каждой точки допускается не более трёх касаний: основное сообщение, повтор через 3 часа без ответа и финальный повтор ещё через 1 час.
- Только основные активные заявки `GREENWICH_INTERNAL`; доп. заявки отдельно не напоминаются.
- Сообщение уходит назначенному активному сотруднику Greenwich с привязанным `telegramChatId`.
- Если Telegram не привязан, склад один раз получает служебное предупреждение с просьбой проверить заявку вручную.
- Неотправленная из-за временного сбоя Telegram запись остаётся в outbox и повторяется следующим запуском.
- Повторная отправка резервируется атомарно в БД, поэтому параллельные cron-запуски не дублируют одно касание.

## Действия в сообщении

- **Всё актуально** — фиксируется подтверждение; склад получает короткое подтверждение в Telegram и центре уведомлений, чтобы действие было наблюдаемым.
- **Будут изменения** — состав и статус заявки не меняются; склад получает отдельный ранний сигнал в Telegram и центре уведомлений.
- **Отменить заявку** — сначала показывается подтверждение. После подтверждения основная и активные дочерние заявки переводятся в `CANCELLED`; закрытую заявку отменить нельзя.

## Рейтинг реакции

- Любой корректный ответ на контрольное сообщение создаёт небольшой положительный балл: система ценит дисциплину, а не только штрафует.
- Если основное сообщение осталось без ответа 3 часа, повторное касание создаёт небольшой штраф рейтинга.
- Если ответа нет ещё час, финальное касание создаёт второй штраф; четвёртого сообщения не бывает.
- Штрафы не фиксируют рейтинг навсегда: после настраиваемой паузы их влияние линейно сходит к нулю.
- Ручная корректировка администратора становится отдельным событием рейтинга и не выключает дальнейшую автоматику.
- Размеры штрафов и сроки восстановления управляются в центре проверки Telegram.
- Текущий рейтинг определяет уровень сотрудника и его скидку в каталоге; уровни и скидки настраиваются там же.

## Инварианты

- Callback принимается только от Telegram-пользователя, чей личный чат сейчас привязан к назначенному сотруднику Greenwich.
- Один контрольный этап принимает только один итоговый ответ; повторные нажатия идемпотентны.
- Смена статусов и запись ответа при отмене выполняются одной транзакцией.
- Telegram и пересчёт достижений выполняются после HTTP-ответа через `scheduleAfterResponse`.
- Кнопки содержат короткий callback payload, укладывающийся в лимит Telegram.

## Приёмка

- [ ] На контрольных датах 30/14/7/3 приходит персональное сообщение с тремя действиями.
- [ ] «Всё актуально» сохраняется и создаёт короткое уведомление склада.
- [ ] «Будут изменения» создаёт ранний сигнал складу, но не меняет заявку.
- [ ] Отмена требует повторного подтверждения и отменяет активную заявку с дополнениями.
- [ ] Повторное нажатие не создаёт повторных действий.
- [ ] Сбой отправки не теряет контрольную точку.
- [ ] Без ответа приходят только два дополнительных касания: через 3 часа и ещё через 1 час.
- [ ] За пропущенные повторы применяются восстанавливаемые штрафы рейтинга без блокировки автоматики.
- [ ] Из админки можно запустить контролируемый боевой сценарий для выбранного сотрудника и его активной заявки и увидеть реальный ответ в журнале.

## Деплой

Перед выкладкой приложения последовательно применить миграции `20260819110000_greenwich_order_reminders`, `20260819170000_greenwich_rating_events_and_reminder_escalation`, `20260820120000_greenwich_rating_loyalty_and_warehouse_stages` и `20260825020000_greenwich_confirmation_day_14`. Vercel не применяет Prisma-миграции автоматически. Webhook и запуск напоминаний используют уже существующие Telegram env и cron.
