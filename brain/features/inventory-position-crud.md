# Быстрое ведение позиций инвентаря

UI: `/inventory/positions`, `/inventory/positions/new`. Основные модули: `PositionEditor.tsx`, `position-form.ts`, `position-workspace.module.css`.

## Пользовательский путь

Компактная панель объединяет поиск, видимость, сортировку и неактивные позиции. Поиск запускается через 300 мс после ввода, Enter/«Найти» — сразу. Сортировка по названию, цене, исправному остатку, дате изменения/создания выполняется над полным загруженным списком без мутации исходного массива.

«Редактировать» раскрывает форму под строкой. Она загружает актуальный серверный снимок и сохраняет с expectedUpdatedAt. «Сохранить» обновляет список и сворачивает форму; ошибка сохраняет черновик. Во время редактирования переключение фильтров и открытие второго редактора недоступно. Закрытие изменённой формы запрашивает подтверждение.

«Новая позиция» открывает ту же форму над списком. Можно сразу указать описание, тип, аренду/закупку, все остатки, фото, видимость, категории и подборки. Отдельный URL добавления тоже возвращает в список после сохранения. Полная карточка остаётся доступна по названию и ссылке внутри редактора; там настраиваются связанные рекомендации.

Удаление доступно из строки с явным подтверждением. Связанные заявки/история запрещают удаление через существующий DELETE. Интерфейс показывает ответ сервера.

## Сохранение и инварианты

- `GET /api/inventory/positions?options=true` возвращает категории и реальные Collection для формы; выборки Item не выполняются. Старый список/API совместимы.
- POST создаёт позицию, связи категорий/подборок и начальные LossRecord атомарно. Сумма недоступных остатков не превышает total. При FK-конфликте нет частично созданной позиции.
- PATCH сохраняет прежнюю Serializable-проверку связанных остатков/CAS и возвращает updatedAt подтверждённой записи.
- Фото сохраняется существующим защищённым photo API. Если данные уже записаны, а фото/итоговое чтение не завершилось, повтор не создаёт вторую позицию и не повторяет тот же PATCH. Изменение полей после частичного сохранения проверяет подтверждённую revision перед следующим PATCH.
- Создание/редактирование сохраняет collectionIds; прежняя полная карточка больше не сбрасывает их в пустой массив. PATCH сохраняет расположение внутри оставленных подборок и изменяет только удалённые/добавленные связи.
- Валидация числа не превращает отрицательный, дробный остаток или ошибочный ввод в ноль. Десятичная запятая поддерживается в цене.
- Скрытие позиции текущими фильтрами после сохранения объясняется сообщением с действием «Показать все».
- Новых таблиц/env/миграций нет. Доставка фото и работа production Storage остаются прежними.
