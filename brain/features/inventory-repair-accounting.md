# Инвентарь: источники ремонта и безопасные остатки

## Инварианты
- Item.inRepair / broken / missing — общие количества, включающие случаи из заявок.
- Ручной ремонт = общий bucket минус незавершённые Incident соответствующего состояния.
- Восстановление уменьшает bucket, но не total. Списание уменьшает оба на одно количество.
- Ручные операции не могут расходовать количество, принадлежащее открытым Incident.
- Изменения выполняются в Serializable; конфликт возвращает 409, интерфейс предлагает обновить данные.
- PATCH позиции не может уменьшить bucket ниже количества открытых случаев из заявок.
- expectedUpdatedAt защищает редактирование позиции от устаревшего снимка.
- Увеличение missing вручную создаёт только добавленную разницу; уменьшение идёт через LossRecord, без перезаписи истории.

## Интерфейс
- /inventory/repair: единый список с источником, поиском, фильтрами и подтверждением количества.
- История показывает закрытые Incident, включая заказчика, создателя заявки и итоги восстановления/списания.
- Создатель заявки не обозначается как виновник поломки.
- История старых ручных ремонтов отсутствует в исходной модели; она не выдумывается.

## Границы
Исторические расхождения production не исправляются автоматически. Сначала ежедневный аудит и сверка конкретных случаев; миграция схемы не требуется.
