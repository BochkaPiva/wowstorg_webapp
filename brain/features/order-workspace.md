# Рабочая карточка заявки и перенос дат

## Цель

Собрать просмотр и редактирование заявки в единый операционный интерфейс и дать ответственному сотруднику безопасно переносить уже оформленную заявку на другой период.

## Границы

- Статусная модель и существующий степпер не меняются.
- Перенос доступен только до выдачи: Grinvich — до согласования включительно, склад — также на этапе сборки.
- На этапах выдачи, приёмки, закрытия и отмены даты заблокированы.

## Затронуто

- UI: `src/app/orders/[id]/page.tsx`, `OrderDateChangeDialog.tsx`.
- API: `POST /api/orders/[id]/dates` для проверки, `PATCH /api/orders/[id]/dates` для применения.
- Prisma: схема не меняется; используются существующие поля дат, частей суток и строк заявки.

## Инварианты

- Проверка и применение используют одинаковый расчёт пересечений резервов.
- Применение повторно проверяет остатки в `Serializable`-транзакции; `P2034` возвращается как `409`.
- До явного подтверждения пользователя заявка не меняется.
- При конфликте можно либо оставить исходные даты, либо удалить только недоступные позиции. Удаление всего состава запрещено.
- Для внутренней заявки перенос после отправки/согласования сметы запускает повторный цикл проверки сметы.
- В режиме складского редактирования финансовый итог, скидка, услуги, налог и маржа собраны в одном правом контуре; промежуточные итоги не дублируются по странице.
- Склад может изменить итог конкретной позиции без изменения срока заявки: UI пересчитывает его в `pricePerDaySnapshot`, а `warehouse-edit` сохраняет новый снимок цены и пересобирает клиентскую смету.
- Ручная сумма позиции задаётся до общей скидки на аренду. Общая скидка по-прежнему применяется отдельным слоем и распределяется по строкам пропорционально.
- Личный список Grinvich использует компактную структуру рабочей очереди: событие, логотип компании, период, сумма, прогресс и действие текущего этапа видны без открытия заявки.
- Быстрые действия в списке используют те же статусные API, что и детальная карточка; отдельной альтернативной статусной логики нет.
- В клиентской карточке итог показывается в шапке один раз, а ниже остаётся компактная расшифровка налога и скидки без складских показателей маржи.
- Wowstorg может мягко отменить заявку на любом активном этапе: данные не удаляются, статус становится `CANCELLED`; `CLOSED` остаётся неизменяемым завершённым фактом.
- Для отмены на этапах `PICKING`, `ISSUED`, `RETURN_DECLARED` API требует отдельный флаг подтверждения освобождения складского резерва.
- Технический перевод на приёмку доступен только Wowstorg для любой незавершённой заявки: текущие количества фиксируются в `issuedQty`, создаётся декларация возврата `OK`, статус атомарно меняется на `RETURN_DECLARED`.
- Технический перевод не начисляет сотруднику Grinvich штраф за просрочку, поскольку действие инициирует склад.

## Приёмка

- [x] Кнопка переноса находится в верхнем рабочем контуре заявки.
- [x] Модальное окно показывает готовность и границы аренды с частями суток.
- [x] Успешная проверка позволяет применить период.
- [x] Конфликт показывает позицию, нужное и доступное количество.
- [x] Можно перенести заявку с удалением недоступных позиций или ничего не менять.
- [x] Карточка после применения обновляется без ручной перезагрузки.
- [x] В редактировании видны оплачиваемые дни, расчёт и сумма каждой позиции.
- [x] Итог позиции можно изменить отдельно, не меняя даты и количество дней заявки.
- [x] Grinvich может согласовать смету или отправить выданную заявку на приёмку прямо из списка.
- [x] Клиентские список и карточка используют единый спокойный визуальный язык без старой градиентной шапки.
- [x] Wowstorg может отменить заявку без удаления на любом активном этапе.
- [x] Wowstorg может технически открыть приёмку, пропустив промежуточные этапы.
