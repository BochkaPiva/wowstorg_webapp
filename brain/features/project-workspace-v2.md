# Project Workspace V2

## Цель

Сделать модульную карточку проекта: фиксированная управленческая шапка, настраиваемая сетка виджетов, надёжное автосохранение, свободная доска и компактная табличная смета без потери существующей бизнес-логики.

## Границы

- Не меняем формулы сметы, резервы и статусы заявок.
- Не создаём вторую сущность задач.
- Не строим полный клон Miro и CRDT в первой версии.
- Не переносим независимые сметы на новый grid до проверки проектной версии.
- Не удаляем legacy UI и проектные поля до завершения rollout.

## Затронуто

- Prisma: creator, участники, layout виджетов, элементы свободной доски, revisions/idempotency.
- API: создание проекта, members, workspace, widgets, batch mutations, estimate batch.
- UI: `/projects`, `/projects/[id]`, адаптеры задач/заявок/контактов/файлов/тайминга/истории, новый estimate grid.
- Инфраструктура: Supabase migrations применяются вручную до включения feature flags.

## Инварианты

- `Project.ownerUserId` — ответственный; `createdByUserId` — создатель.
- Ответственный всегда входит в `ProjectMember`.
- Шапка не является виджетом; компактные финансы читаются из основной сметы.
- `ESTIMATE` и `ORDERS` обязательны.
- Виджет хранит layout/config, но не копирует бизнес-данные.
- Скрытие виджета не удаляет данные.
- Задачи — существующие `WorkTask` с `projectId`.
- Файлы — существующие `ProjectFile` в Supabase Storage.
- Финансовые итоги UI, серверного read model, XLSX, очереди и аналитики совпадают. Исторический route `/estimate/pdf` сейчас отдаёт XLSX и не является отдельным PDF-builder.
- Архивный проект read-only на сервере.
- Быстрые изменения сохраняются через optimistic UI, per-entity queue и revisions без full reload.

## Этапы

1. Финансовые contract tests и технические spikes.
2. Создатель, ответственный и участники.
3. Модель layout и backfill.
4. Новый экран создания.
5. Workspace shell с текущими модулями.
6. Режим настройки.
7. Надёжный mutation queue/offline recovery.
8. Свободная доска.
9. Табличная смета.
10. Шаблоны/custom columns и затем независимые сметы.

## Реализованный фундамент (2026-08-28)

- В проекте отдельно фиксируются создатель и ответственный.
- Добавлены участники проекта с обязательным участием ответственного.
- Добавлен registry рабочих блоков и сохранение стартового 12-колоночного layout.
- При создании проекта выбираются ответственный, участники и нужные блоки; смета и заявки подключаются обязательно.
- Преобразование независимой сметы создаёт тот же обязательный фундамент проекта.
- Существующие полные проекты получают создателя, ответственного-участника, смету и заявки через backfill-миграцию.
- Карточка показывает сохранённый набор рабочих модулей и открывает существующие блоки без дублирования данных.
- Inline-настройка атомарно сохраняет ответственного, участников, порядок, видимость и разрешённую ширину модулей.
- Конфликт параллельных изменений определяется по `Project.revision` и возвращает 409 вместо тихой перезаписи.
- Сохранённые порядок и ширина применяются к реальной 12-колоночной сетке карточки; на узком экране все модули складываются в одну колонку.
- Смета, заявки, задачи, контакты, тайминг, файлы, заметки и журнал являются самостоятельными модулями, а не вкладками одного скрывающего блока.
- Модули можно переставлять мышью или клавиатурными стрелками; доступна отмена локальных изменений раскладки до сохранения.
- Успешное сохранение команды и layout обновляет локальный read model без полной перезагрузки страницы.
- Быстрые изменения свободной доски проходят через coalescing-очередь с idempotency, revisions, retry и локальным восстановлением после offline/reload.
- Доска поддерживает заметки, стикеры, заголовки, чек-листы и ссылки, а также живые связи с задачами, заявками, файлами и разделами сметы.
- Блоки можно перемещать, менять по размеру, дублировать, отменять и восстанавливать; удаление остаётся soft-delete на сервере.
- Несколько блоков можно выбрать, собрать в именованную группу, перемещать комплектом, перегруппировать и распустить без удаления содержимого.
- Действуют серверные и клиентские лимиты: до 200 блоков на доске, до 50 пунктов чек-листа и до 50 блоков в группе.
- Локальные разделы сметы получили компактный табличный режим без второй финансовой модели; карточный вид оставлен как совместимый fallback.
- Новая карточка имеет два независимых серверных аварийных переключателя: `PROJECT_WORKSPACE_V2_ENABLED` и `PROJECT_ESTIMATE_GRID_V2_ENABLED`. Без явного значения `1/true/on/v2` они безопасно выключены. Их значения приходят в разрешённом API read model и не попадают в клиентский bundle как `NEXT_PUBLIC_*`. Для точечной внутренней проверки доступны `?workspace=legacy` и `?workspace=v2`.
- Первичная загрузка проекта отличает 404 от сетевой/API-ошибки, предлагает повтор и игнорирует запоздавший ответ более старого запроса.
- В таблице работают Enter/Shift+Enter по колонке и вставка диапазона из Excel/Google Sheets с автоматическим добавлением строк.
- Изменения сметы сохраняются последовательно и без полного reload; быстрые правки объединяются, локальный черновик восстанавливается после сбоя, а опасное удаление всех разделов требует ручного подтверждения.
- Снимок сметы сохраняется одной атомарной транзакцией с revision/CAS-проверкой: параллельная вкладка получает 409 вместо тихой перезаписи более свежих данных. Синхронизация вкладок через `BroadcastChannel` обновляет чистую вкладку автоматически, а вкладку с локальным черновиком ставит на паузу и требует явно выбрать серверную или локальную версию.
- Для больших смет добавлены закреплённая шапка таблицы, выбор отдельных или всех строк и массовое дублирование/удаление одним изменением черновика.
- Выбранные строки можно копировать TSV-диапазоном, вставлять над/под текущей позицией и обходить стрелками; возврат в длинную смету восстанавливает позицию прокрутки в рамках вкладки.
- Клиентский экран, серверный read model, список проектов, аналитика и XLSX используют единый расчёт строк. Дополнительные внутренние расходы не теряются, налог на наличные расходы округляется один раз от общей наличной суммы, а regression-тест проверяет одинаковые итоги на смете из 70 строк.
- Текущую компоновку блоков можно сохранить как личный шаблон и применить при создании нового проекта. В шаблоне нет бизнес-данных: только порядок, видимость и допустимые размеры модулей; обязательные смета и заявки всегда включены.
- Локальная табличная смета поддерживает до 12 пользовательских вспомогательных колонок типов «текст», «число», «дата», «флажок» и «формула»; порядок и ширина сохраняются вместе с ревизионным снимком сметы.
- Формулы используют стабильные ключи колонок и ограниченную грамматику без JavaScript (`+`, `-`, `*`, `/`, `%`, скобки, `round`, `min`, `max`, `abs`). Формульные результаты вычисляются в браузере и не сохраняются как источник истины.
- Вспомогательные ячейки намеренно не входят в расчёт выручки, расходов, налогов, маржи, аналитику и XLSX-выгрузки. Это закреплено отдельным regression-тестом.
- Проверенный компактный табличный режим переиспользуется в независимых сметах. Их отдельная сущность, финансовая модель и API-контракт не изменены; проектные вспомогательные колонки туда не переносятся.
- Тяжёлые модули карточки загружаются отдельно и имеют локальные skeleton/error boundary: сбой контактов, сметы, файлов, доски или тайминга не обрушает всю страницу проекта.
- В режиме настройки доступны разрешённые ширина и высотный пресет каждого блока. Высота задаёт безопасный `min-height`, поэтому длинное содержимое не обрезается.
- Обзор проекта оформлен как спокойный центр управления: виджеты используют плотную 12-колоночную композицию, имеют собственное меню действий и могут локально сворачиваться с автоматической перепаковкой сетки. Серверные порядок, ширина, высота и видимость по-прежнему меняются в едином конструкторе карточки.
- Табличная смета получила регулируемую ширину основных колонок и маркер протягивания значения по строкам. Настройки ширины сохраняются в браузере, а протягивание использует тот же последовательный autosave и не создаёт отдельную финансовую модель.

Кодовый срез завершён. Операционный gate перед включением: вручную применить общую миграцию в Supabase SQL Editor, выполнить validation queries из runbook, затем пройти браузерную приёмку старого и нового проекта на preview. Полный снимок намеренно сохраняется одной batch-транзакцией, а не сотнями отдельных Prisma-операций.

## Приёмка

- [ ] Старые проекты мигрированы без копирования/потери данных.
- [x] Ответственный выбирается и переназначается.
- [x] Модули можно переставлять, менять по размеру, скрывать и возвращать.
- [x] Обязательные модули нельзя удалить.
- [x] Скрытие не меняет заявки, задачи, файлы, контакты или финансы.
- [x] Нет общего reload после cell edit.
- [x] Быстрые последовательные действия и конфликт двух вкладок защищены revision/CAS и явным разрешением конфликта.
- [x] Смета на 50–70 строк поддерживает клавиатуру, вставку диапазона и sticky header.
- [x] Финансовый parity UI/read model/XLSX подтверждён 70-строчным fixture.
- [x] Серверные feature flags позволяют мгновенно вернуть legacy UI и карточный вид сметы.
