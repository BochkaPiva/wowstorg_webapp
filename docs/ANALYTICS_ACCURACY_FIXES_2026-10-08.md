# Исправление достоверности аналитики — 08.10.2026

Продолжение [аудита](ANALYTICS_DATA_AUDIT_2026-10-08.md). Правки локальные; публикация не выполнялась. Архитектурный контракт: [ADR 016](../brain/decisions/016-analytics-financial-fact-recognition.md).

## Что изменилось

1. Общие даты обзора, проектов, клиентов и реквизита. Миграция localStorage v2 → v3 берёт период обзора; периоды бонусов и сверки независимы.
2. Завершённый проект целиком признаётся по окончанию события; при отсутствии окончания — по началу. Прогноз сохраняет пересечение интервалов. Прогноз соседних месяцев нельзя суммировать как факт.
3. Динамика UI и Excel питается единым реестром фактов: source, id, customerId, date, revenue, profit. Все суммы агрегируются в копейках; UI сохраняет до двух знаков, Excel — два знака.
4. Клиенты: общий факт, отдельные суммы проектов и самостоятельных заявок, отдельный совокупный прогноз активных работ. Клиенты только с активными самостоятельными заявками больше не пропадают.
5. Проекты без дат показываются в раскрытии «Без дат» и в отдельном листе Excel, вне финансовых итогов. Сметы не редактируются, даты не угадываются.
6. Таблица реквизита использует весь каталог. Закрытые выдачи самостоятельных заявок и проектов разделены; деньги связанных заявок повторно не прибавляются. Неизвестная закупочная цена отличается от заданной нулевой.
7. Ложный показатель «ROI периода» и «валовая прибыль» реквизита убраны из UI/Excel: текущая стоимость всего парка не является расходами периода. Сохранён явно подписанный показатель «выручка / парк».
8. Риски проектов больше не обрезаются до 30 записей. Отменённые и архивные не получают финансовый риск низкой/отрицательной маржи; stale KPI относится только к активным.
9. Бонусные доли сохраняют копейки и в сумме точно равны пулу. Сверка явно показывает период снимка и сравнение всего файла с всем фактом сайта, не только MATCHED.
10. В деталях проекта указано число учитываемых смет; fallback чернового реквизита не скрывает известный бюджет. Основные SQL/money/helpers, ставки, auth и бизнес-записи не менялись.

## Проверки

- npm test: 259 тестов, 46 файлов. Новые регрессии: финансовый реестр, граничные даты, неполные даты, включённость версий, копейки, связанные заявки, полный каталог, нулевая цена, 40 рисковых проектов, клиенты только с прогнозными заявками, реальные ячейки XLSX.
- npm run build: успешно.
- Scoped ESLint по затронутым исходникам/тестам: без ошибок и предупреждений.
- Browser QA шести вкладок при desktop/mobile: общий период основных вкладок, независимая сверка, shared cache, поиск, страницы, детали, retry, preview guard. Нет горизонтального overflow страницы и pageerror. Это синтетические перехваченные API, не проверка авторизации production.
- Отдельно read-only проверены реальные агрегаты, полнота каталога и соответствие сметам. В harness assertTotals сравнивает факты, клиентские суммы, месячные суммы, прогноз и бонусные доли.

## Не устранённые ограничения первичных данных

- На момент аудита: четыре завершённых проекта без обеих дат, 240 437,70 ₽, оставались вне итогов. **Уточнение 09.10.2026:** по запросу владельца теперь учитываются по записанной дате закрытия (см. ADR 016), без изменения карточек. Выше приведены исторические суммы до этого уточнения. Даты по заголовкам по-прежнему не назначаются.
- Разные смысловые названия клиента могут требовать ручного объединения; проверка одинаковых normalizedName не доказывает отсутствие всех бизнес-дублей.
- Факт — расчёт по текущим сметам и ценовым снимкам заявок, не банковская выписка, не вся внешняя история агентства. Внешний Excel не подмешивается в факт.
- Все связанные заявки исключаются из самостоятельного факта; полнота их включённости в учитываемые версии смет остаётся ответственностью первичных данных. Проверено совпадение текущих смет, а не независимая правильность каждого первичного расхода.
- Legacy поля API ltvMixed, grossProfit, roiPercent сохранены для совместимости; новые UI/Excel не используют их как LTV, прибыль или ROI периода. Старый отдельный endpoint profitability не менялся и не используется этим дашбордом.
- Настоящий импорт и production auth не проверялись новым проходом; миграция БД не требуется.
