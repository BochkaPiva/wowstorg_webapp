# Greenwich Loyalty V2

## Сценарий продукта

Сотрудник начинает рабочий день с дашборда, где видит рейтинг, действующую скидку, место в месяце и конкретные действия, которые сохранят или улучшат результат. Бот к 11:00 Омска напоминает только о действительно актуальных этапах. Если действие просрочено, сотрудник сначала получает ясное предупреждение с дедлайном; штраф появляется лишь после игнорирования.

Склад управляет системой из одного центра: видит сотрудников и динамику, редактирует уровни и веса будущих событий, создаёт предложения на выбранные товары, проверяет очередь и ошибки напоминаний.

## События рейтинга

| Событие | По умолчанию | Восстановление |
|---|---:|---|
| Ответ на контроль актуальности | +1 | — |
| Пропущено повторное подтверждение | -1 | да |
| Пропущено финальное подтверждение | -2 | да |
| Не согласовано после предупреждения | -3 | да |
| Возврат после срока | -5/день, максимум -25 | да |
| Полностью исправный возврат | +5 | — |
| Нужен ремонт / сломано | -1/ед. | нет |
| Потеряно | -3/ед. | нет |
| Ручная корректировка | вручную | нет |

Значения редактируются и применяются только к новым событиям.

## Правило согласования близко к дате

- Между созданием и `readyByDate` меньше трёх календарных дней: штрафа нет.
- За два дня до `readyByDate` обычная заявка всё ещё не согласована: предупреждение Greenwich и сигнал складу.
- Если до следующего рабочего контрольного запуска статус не продвинулся, создаётся один восстанавливаемый штраф.
- Отмена и закрытые статусы прекращают сценарий.

## Персональные предложения

Предложение имеет получателя, заголовок, описание, процент, период действия и набор товаров. Для товара применяется `max(скидка уровня, активные предложения)`. В интерфейсе это одна финальная цена и одна подпись-источник. Снимок сохраняется в строке заказа.

## Месячный лидер

Месяц считается в `Asia/Omsk`. Кандидат должен иметь автоматическое событие или закрытую заявку в месяце. Сортировка: месячная сумма, аккуратные закрытия, меньше отрицательных событий, текущий рейтинг, имя. При отсутствии активности победитель не назначается.

## Эксплуатация

- Cron можно запускать чаще одного раза в день: уникальные ключи защищают от дублей.
- Календарные сообщения становятся доступными к отправке в 11:00 Омска.
- Telegram-сбой сохраняется для повтора; бизнес-операция не откатывается из-за уведомления.
- Перед production применить Prisma-миграцию вручную; Vercel её не применяет.
