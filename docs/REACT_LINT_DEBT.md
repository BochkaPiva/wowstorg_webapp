# План устранения React ESLint-долга

## Правила работы

- Исходная точка 10.10.2026: 164 ошибки, зафиксированные в `scripts/quality/eslint-baseline.json`.
- Исправлять причины, не отключать правила и не переносить setState в таймер/микрозадачу для обхода проверки.
- Каждый пакет уменьшает baseline по исправленным файлам/правилам. `lint:ci` отклоняет новые ошибки и неиспользуемые старые допуски.
- Проверять сохранение черновиков, внешние обновления, закрытие/повторное открытие, SSR/hydration и cleanup там, где эти сценарии затронуты.
- Перед выпуском: `npm run build:verified`. Полный `npm run lint` останется красным до завершения всех пакетов.

## Следующие пакеты

1. Изолированные формы/диалоги: reset при открытии и смене сущности, сохранение пользовательского ввода. Отдельно — асинхронные загрузки с отменой/защитой от устаревших ответов.
2. Каталог, корзина и задачи: состояния запросов и черновиков, без изменения резервирования/цен. Нужны сценарии гонок запросов и повторных действий.
3. КП, сметы и доска: refs/immutability/memoization; сначала разобрать владение изменяемым состоянием и подписки, затем правки с проверкой autosave, undo/redo и экспорта. Это наиболее рискованный пакет.
4. Финальная проверка: нулевой baseline, чистый строгий lint, затем удаление временного механизма допусков. Предупреждения ESLint учитывать отдельно — они не входят в эти 164/158 ошибок.

Порядок можно менять по риску/пересечениям. Цель — устранить весь долг; пакет 1 не является завершением этой работы.

Подходы: [React — состояние без лишних effects](https://react.dev/learn/you-might-not-need-an-effect), [React — SSR snapshots](https://react.dev/reference/react/useSyncExternalStore).
