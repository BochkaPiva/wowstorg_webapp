# Уведомления в Telegram

Бот отправляет уведомления в чаты при событиях по заявкам. Отправка **best-effort**: ошибки не прерывают операции на сайте.

## Минимум действий с вашей стороны

1. **`.env` в корне проекта** (рядом с `package.json`): задать `TELEGRAM_BOT_TOKEN`, `TELEGRAM_NOTIFICATION_CHAT_ID`; для супергруппы с темами — ещё `TELEGRAM_NOTIFICATION_TOPIC_ID`. Сохранить файл и **перезапустить** `npm run dev` (Next подхватывает env при старте).
2. **Залогиниться складом** (роль WOWSTORG) → **Админка** → **Telegram** → «Обновить статус». В верхней диагностике должны быть подключены Bot API, складской маршрут и webhook. Затем выбрать сценарий и получателя и выполнить контрольную отправку.
3. Если тест не пришёл — в окне терминала с `npm run dev` искать строки **`[Telegram]`** (там будет текст ошибки от API Telegram: нет прав, неверный chat_id, не тот топик и т.д.).

Личные уведомления Greenwich: у пользователей с ролью Greenwich в **Админка → Пользователи** должен быть заполнен **Telegram Chat ID**, а пользователь должен написать боту `/start`.

Если настроен Telegram webhook, после `/start` бот отвечает:
- привязанному сотруднику Greenwich — персональным приветствием и подтверждением, что уведомления подключены;
- непривязанному пользователю — показывает его Telegram ID, который нужно занести в карточку пользователя.

Для webhook нужны `NEXT_PUBLIC_APP_URL`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` и одноразовая настройка через Bot API:

```bash
curl -X POST "https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/setWebhook" \
  -d "url=https://your-domain/api/telegram/webhook" \
  -d "secret_token=<TELEGRAM_WEBHOOK_SECRET>"
```

### Скорость интерфейса

После успешной записи в БД уведомления в Telegram ставятся в очередь **`after()`** (`next/server`): HTTP-ответ клиенту уходит **сразу**, отправка в `api.telegram.org` выполняется **после** ответа (кнопки не ждут сеть Telegram). В ответах создания заявки и отмены в JSON приходит `notification.queued: true` и поясняющий `message` (реальный результат отправки — только в логах сервера: `[notify…]`, `[Telegram]`).

### Фоновый режим уведомлений

**Сейчас используется отложенная отправка** через `scheduleAfterResponse` → `after()` из Next.js. Реализация: `src/server/notifications/schedule-after-response.ts` (обёртка с `try/catch` и логом ошибок).

### Подтверждение ранних заявок Greenwich

Runner проверяет основные активные заявки Grinvich и за **30, 14, 7 и 3 дня** до начала аренды отправляет назначенному сотруднику персональное сообщение с кнопками:

- **Всё актуально** — подтверждение сохраняется, склад получает короткое подтверждение в Telegram и центре уведомлений;
- **Будут изменения** — склад получает ранний сигнал в Telegram и центре уведомлений, сама заявка пока не меняется;
- **Отменить заявку** — после дополнительного подтверждения отменяются основная и активные дочерние заявки. Закрытую заявку отменить нельзя.

Каждая контрольная точка записывается в `GreenwichOrderReminder`. Если ответа нет 3 часа, бот отправляет повтор; если ответа нет ещё час — третье, финальное сообщение. Дальше цепочка останавливается. Повторы резервируются атомарно, чтобы параллельные cron-запуски не создали дубль. Неуспешная отправка остаётся в очереди и повторяется следующим запуском. Если сотруднику Greenwich не привязан личный Telegram, склад получает одно служебное предупреждение вместо потери напоминания.

Второе и третье касания создают отдельные штрафные события рейтинга. Их влияние восстанавливается со временем по политике, которую склад меняет в **Админка → Telegram**. Ручная корректировка рейтинга в карточке пользователя больше не выключает автоматический расчёт.

Любой итоговый ответ создаёт небольшой положительный балл. Итоговый рейтинг выбирает управляемый уровень лояльности и скидку Greenwich в каталоге. В той же админке настраиваются награда за исправный возврат, веса ремонта/потери, дневной штраф и потолки, чтобы единичный инцидент не мог непропорционально обнулить репутацию.

### Дисциплина этапов склада

Тот же runner отправляет складу отдельные операционные напоминания, когда заявка готова к следующему фактическому действию: пора начать сборку, аренда уже началась, но выдача не отмечена, период завершён и пора оформить возврат, либо Grinvich заявил возврат, а приёмка склада не завершена. Эти сообщения не меняют рейтинг Grinvich: ответственность склада остаётся отдельной от клиентской репутации.

Календарные сообщения склада и Grinvich отправляются только в рабочем окне `11:00–21:59 Asia/Omsk`. Напоминание Grinvich об отправке возврата на приёмку учитывает выбранную половину последнего дня аренды: для `MORNING` оно открывается с `11:00`, для `EVENING` — с `18:00`. Запуск каждые 15 минут даёт повторную попытку при временном сбое Telegram; запись идемпотентности создаётся только после успешной отправки. Если всё оставшееся рабочее окно было недоступно, незакрытая заявка догоняется следующим утром без повторной отправки уже доставленного сообщения. Пользовательские напоминания задач с явно выбранным временем не ограничены рабочим окном.

На Vercel Hobby в `vercel.json` оставлен ежедневный резервный запуск в `11:05 Asia/Omsk`. Для проверки каждые 15 минут используется `.github/workflows/reminders-hourly.yml`; в GitHub Actions должен быть задан `CRON_SECRET`, совпадающий с production-переменной Vercel.

GitHub workflow выводит HTTP-статус и JSON-ответ runner без значения секрета. У каждого запуска API есть `runId`: при ошибке тот же идентификатор попадает в логи Vercel как `[reminders-run:<runId>]`, поэтому сбой авторизации (`403`) легко отличить от ошибки самой обработки (`500`). После изменения `CRON_SECRET` в Vercel нужен новый production deployment, иначе запущенная функция продолжит видеть старое окружение.

### Быстрые действия Grinvich

- Смета: `Согласовать смету` выполняется прямо в Telegram; изменения открываются на сайте.
- После выдачи и в день возврата: `Всё в порядке — на приёмку` помечает все выданные позиции как исправные. Если есть грязное, ремонт, поломка или потеря, открывается полная форма сайта.
- После закрытия: `4★` и `5★` сохраняются одним нажатием. Для `1–3★` бот просит открыть форму и добавить комментарий, чтобы низкая оценка не потеряла причину.

Каждый callback повторно проверяет личный Telegram, владельца заявки и её текущий статус. Повторное или устаревшее нажатие не создаёт второй переход и убирает неактуальную клавиатуру.

### Деплой и Россия (ECONNRESET, VPN, `fetch failed`)

**Проблема на вашем ПК** (блокировка/замедление `api.telegram.org`) — это **не** то же самое, что на проде.

| Где крутится приложение | Исходящий запрос к Telegram |
|-------------------------|------------------------------|
| **Vercel / EU-US VPS / Railway / Fly.io и т.п.** | Сервер **вне РФ** обычно ходит в `api.telegram.org` **без VPN** — блокировки РФ на него не распространяются. **VPN на сервере не нужен.** |
| **Сервер в РФ** (свой VPS, локальный хостинг) | Исходящий трафик сервера к Telegram может **снова обрываться** или таймаутиться. Нужен **выход через прокси** (`TELEGRAM_HTTPS_PROXY` / `HTTPS_PROXY` на прокси с зарубежным выходом) или **перенос хостинга** за регион. |

Пользователи из России в браузере открывают сайт как обычно; важно только **где сервер выполняет** `fetch` к `api.telegram.org`.

Для **локальной разработки** в РФ: VPN на ПК или `TELEGRAM_HTTPS_PROXY=http://127.0.0.1:ПОРТ` к локальному прокси из VPN-клиента (см. таблицу переменных ниже).

### Отладка на localhost

1. Зайти под **WOWSTORG** (склад) → **Админка** → **Telegram** (`/admin/telegram`). Центр проверки показывает состояние Bot API, склада, webhook и привязок Greenwich.
2. Выбрать один из сценариев уведомлений и явного получателя: склад, конкретного сотрудника Greenwich или произвольный `chat_id`. Сообщение всегда помечается как тестовое.
3. Для напоминаний Grinvich за 30/14/7/3 дня проверить inline-кнопки в Telegram. Callback попадёт в настоящий webhook, но префикс `tgtest:` не позволит изменить данные приложения.
4. Результат отправки отображается в локальной истории на странице. Массовая отправка Greenwich находится в дополнительных проверках и требует отдельного подтверждения.

Для проверки полного production-сценария вверху центра есть отдельный **боевой end-to-end тест**. Оператор выбирает подключённого сотрудника Grinvich, его активную реальную заявку и контрольную точку 30/14/7/3 дня. Сообщение использует production callback `gcf:`: подтверждение и будущие изменения уведомляют склад, а подтверждённая отмена действительно отменяет основную заявку и активные дополнения. Перед отправкой интерфейс требует явного подтверждения, а фактический ответ сохраняется в серверном журнале на странице.
5. В терминале с `npm run dev` после теста или создания заявки смотреть **`[Telegram]`** (и при необходимости **`[notifyOrderCreated]`** и т.п.).
6. Вручную: **GET `/api/admin/telegram`** возвращает состояние и каталог сценариев. **POST** принимает `kind`, `scenarioId` и идентификатор получателя при необходимости, например `{"kind":"warehouse","scenarioId":"new-order"}` или `{"kind":"dm","chatId":"…","scenarioId":"connection"}`.
7. Файл **`notification-debug.log`** в корне (если сервер может писать на диск).

Если в логах `ПРОПУСК: нет TELEGRAM_BOT_TOKEN` или нет ID чата — проверьте `.env` в корне проекта и перезапустите `next dev`. Если ошибка HTTP от Telegram (например *chat not found*, *bot was blocked*) — проверьте, что бот добавлен в чат, для супергрупп с темами верно `TELEGRAM_NOTIFICATION_TOPIC_ID`.

**Типичные ответы Telegram (теперь в ответе API и в админке видно текст дословно):**

| Текст от API | Что сделать |
|--------------|-------------|
| `Bad Request: chat not found` | Неверный `TELEGRAM_NOTIFICATION_CHAT_ID` (для супергрупп ссылка начинается с `-100…`). |
| `Bad Request: message thread not found` | Неверный `TELEGRAM_NOTIFICATION_TOPIC_ID` или сообщение не в тему (форум). |
| `Forbidden: bot was kicked…` / `not a member` | Бота удалили из группы или не добавили — добавьте бота и дайте право писать. |
| `Unauthorized` | Неверный `TELEGRAM_BOT_TOKEN` (перевыпустите у @BotFather). |
| Таймаут (до 25–120 с) | Запрос к `https://api.telegram.org` не успел за `TELEGRAM_SEND_TIMEOUT_MS`. Часто: **блокировка или фильтрация** API у провайдера, корпоративный фаервол, нужен **VPN/прокси** на машине с сервером. Проверка с той же машины: `curl -sS "https://api.telegram.org/bot<TOKEN>/getMe"` — должен вернуться JSON с `"ok":true`. В `.env` можно задать `TELEGRAM_SEND_TIMEOUT_MS=45000` (макс. 120000) и перезапустить `next dev`. |
| `fetch failed` (без деталей) | Ошибка **до получения HTTP-ответа** (сеть/TLS/DNS). В логах и в API теперь подставляется цепочка `cause` (например `ENOTFOUND`, `ECONNREFUSED`). Если по-прежнему неясно — с той же машины выполните `curl https://api.telegram.org` и `nslookup api.telegram.org`. |

## Переменные окружения

| Переменная | Описание |
|------------|----------|
| `TELEGRAM_BOT_TOKEN` | Токен бота (получить у [@BotFather](https://t.me/BotFather)). |
| `TELEGRAM_NOTIFICATION_CHAT_ID` | ID чата/группы склада (приоритетное имя; альтернатива — `TELEGRAM_WAREHOUSE_CHAT_ID`). |
| `TELEGRAM_NOTIFICATION_TOPIC_ID` | ID топика в супергруппе (альтернатива — `TELEGRAM_WAREHOUSE_TOPIC_ID`). |
| `TELEGRAM_WAREHOUSE_CHAT_ID` | То же, что чат склада (если не задан `TELEGRAM_NOTIFICATION_CHAT_ID`). |
| `TELEGRAM_WAREHOUSE_TOPIC_ID` | То же, что топик (если не задан `TELEGRAM_NOTIFICATION_TOPIC_ID`). |
| `TELEGRAM_GREENWICH_CHAT_ID` | ID чата/канала для уведомлений Greenwich (сметы, сборка, выдача, приёмка). |
| `TELEGRAM_WEBHOOK_SECRET` | Секрет входящего webhook для команды `/start`; передается в `setWebhook` как `secret_token`. |
| `NEXT_PUBLIC_APP_URL` | Базовый URL сайта (для ссылок «Открыть заявку»), например `https://wowstorg.ru`. |
| `TELEGRAM_SEND_TIMEOUT_MS` | Таймаут HTTP к Bot API (по умолчанию 25000, максимум 120000). Используется и как **таймаут установки TCP/TLS** к `api.telegram.org` (через undici). |
| `TELEGRAM_HTTPS_PROXY` | HTTP-прокси для запросов только к Telegram API, например `http://127.0.0.1:7890` (порт «Mixed port» в Clash / аналог). Если до `api.telegram.org` **Connect timeout** без VPN — включите VPN и укажите локальный прокси. Альтернативные имена: `TELEGRAM_PROXY`, `HTTPS_PROXY`. |

Если `TELEGRAM_BOT_TOKEN` не задан, уведомления не отправляются.

## События и получатели

| Событие | Куда | Содержимое |
|---------|------|------------|
| **Новая заявка** | Склад | Заказчик, Greenwich, мероприятие, даты, ссылка. |
| **Смета отправлена** | Grinvich + Склад | Полный текст сметы (позиции, аренда, доп. услуги, сумма). В личном сообщении Grinvich доступны безопасная кнопка `Согласовать смету` и ссылка для запроса изменений. Callback повторно проверяет владельца и актуальный статус заявки. |
| **Запрошены изменения** | Склад | Greenwich внёс правки, нужно отправить смету заново. |
| **Смета согласована** | Склад | Можно начинать сборку. |
| **Склад внёс изменения** | Greenwich | Дифф: что добавлено/удалено/изменено по позициям и по заявке, «требуется повторное согласование». |
| **Начата сборка** | Greenwich | Ссылка на заявку. |
| **Заказ выдан** | Grinvich | Ссылка и безопасная отправка исправного возврата на приёмку. |
| **Ожидает приёмки** | Склад | Greenwich отправил на приёмку. |
| **Приёмка завершена** | Grinvich | Заявка закрыта, кнопки оценки `1…5` и ссылка для комментария. |
| **Заявка отменена** | Склад + Greenwich | Ссылка. |
| **Проверка актуальности за 30/14/7/3 дня** | Назначенный Grinvich | Данные заявки и inline-кнопки: актуально, будут изменения, отменить. |
| **Greenwich предупредил о будущих правках** | Склад | Ранний сигнал без изменения состава или статуса заявки. |
| **Этап склада завис** | Склад | Сборка, выдача, возврат или приёмка, которые пора подтвердить в системе. |

Формат сообщений: заголовок с эмодзи, блок с данными заявки, при необходимости — состав сметы или дифф изменений, пустая строка, ссылка на заявку. Используется HTML-разметка Telegram; пользовательский ввод экранируется.

Первая строка формулируется как короткий операционный итог и должна целиком читаться в шторке телефона. Подробные составы, суммы и диффы ниже сохраняются: склад использует их при разборе изменений.
